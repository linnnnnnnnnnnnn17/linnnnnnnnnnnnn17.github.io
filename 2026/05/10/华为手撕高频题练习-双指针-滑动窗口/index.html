LC 3 无重复字符的最长子串 30次

题目链接：LC 3 无重复字符的最长子串

题目描述

给定一个字符串 s ，请你找出其中不含有重复字符的 最长 子串 的长度。

示例 1:

输入: s = “abcabcbb”
输出: 3
解释: 因为无重复字符的最长子串是 “abc”，所以其长度为 3。注意 “bca” 和 “cab” 也是正确答案。

示例 2:

输入: s = “bbbbb”
输出: 1
解释: 因为无重复字符的最长子串是 “b”，所以其长度为 1。

示例 3:

输入: s = “pwwkew”
输出: 3
解释: 因为无重复字符的最长子串是 “wke”，所以其长度为 3。
请注意，你的答案必须是 子串 的长度，”pwke” 是一个子序列，不是子串。

提示：

0 <= s.length <= 5 * 10^4
s 由英文字母、数字、符号和空格组成

思路及必要说明

这是一道经典的滑动窗口题目，核心是维护一个窗口内的字符不重复。

关键观察：

  • 子串是连续的，要求所有字符互不相同
  • 需要找到最长的满足条件的子串长度

滑动窗口策略：

  1. 右指针扩展窗口：不断向右移动右指针，将字符加入窗口
  2. 左指针收缩窗口：当遇到重复字符时，移动左指针直到窗口内无重复字符
  3. 维护窗口状态：使用哈希集合记录当前窗口内的字符

具体实现：

  • 使用 left 和 right 两个指针表示窗口的左右边界
  • unordered_set 存储窗口内的字符，O(1) 时间判断字符是否存在
  • 每次右指针移动时，若当前字符已在窗口中，则不断移动左指针并移除字符，直到窗口内无重复
  • 每次更新窗口后，计算窗口长度并更新最大值

时间复杂度：O(n)，每个字符最多被访问两次（一次加入窗口，一次移出窗口）
空间复杂度：O(min(m, n))，m 是字符集大小（本题最多 128）

LC 42 接雨水（双指针/单调栈） 11次

题目链接：LC 42 接雨水（双指针/单调栈）

题目描述

给定 n 个非负整数表示每个宽度为 1 的柱子的高度图，计算按此排列的柱子，下雨之后能接多少雨水。

示例 1：

输入：height = [0,1,0,2,1,0,1,3,2,1,2,1]
输出：6
解释：上面是由数组 [0,1,0,2,1,0,1,3,2,1,2,1] 表示的高度图，在这种情况下，可以接 6 个单位的雨水（蓝色部分表示雨水）。

示例 2：

输入：height = [4,2,0,3,2,5]
输出：9

提示：

n == height.length
1 <= n <= 2 * 10^4
0 <= height[i] <= 10^5

ACM完整代码

思路及必要说明

这是一道经典的双指针题目，核心思想是利用左右指针从两端向中间移动，计算每个位置能接的雨水量。

关键观察：

  • 每个位置能接的雨水量取决于其左右两侧的最大高度
  • 当前位置能接的水量 = min(左侧最大高度, 右侧最大高度) - 当前高度
  • 如果当前高度 >= min(左最大, 右最大)，则不能接水

双指针策略：

  1. 初始化：左指针在数组起点，右指针在数组终点
  2. 维护左右最大值：分别记录从左边到当前位置的最大高度 pre_max，和从右边到当前位置的最大高度 suf_max
  3. 移动指针：比较 pre_max 和 suf_max，移动较小的那一侧的指针
  4. 计算接水量：在移动指针前，计算当前位置能接的水量

为什么这样做是正确的？

  • 如果 pre_max < suf_max，那么左侧的最大高度决定了当前位置能接的水量，移动左指针
  • 如果 suf_max <= pre_max，那么右侧的最大高度决定了当前位置能接的水量，移动右指针
  • 这样保证了每一步都在计算能确定的接水量

时间复杂度：O(n)，只需一次遍历
空间复杂度：O(1)，只使用常量空间

单调栈解法

单调栈思路说明

这是接雨水问题的另一种经典解法，使用单调栈来寻找每个凹槽。

关键观察：

  • 当遇到一个比栈顶元素高的柱子时，可能形成一个可以接水的凹槽
  • 栈中维护的是单调递减的柱子下标，栈顶是最近的较低柱子

单调栈策略：

  1. 维护单调递减栈：栈中存储柱子下标，对应的高度从栈底到栈顶单调递减
  2. 遍历每个柱子：
    • 如果当前柱子高度 <= 栈顶柱子高度，直接入栈
    • 如果当前柱子高度 > 栈顶柱子高度，说明找到了一个凹槽的右边界
  3. 计算凹槽面积：
    • 弹出栈顶作为凹槽底部（mid）
    • 新的栈顶为凹槽左边界（left）
    • 当前柱子为凹槽右边界（i）
    • 凹槽宽度 = right - left - 1
    • 凹槽高度 = min(左边界高度, 右边界高度) - 底部高度
    • 累加凹槽面积到答案

时间复杂度：O(n)，每个元素最多入栈和出栈一次
空间复杂度：O(n)，最坏情况下栈存储所有元素

为什么这样做是正确的？

  • 单调栈保证了栈中元素始终是递减的，确保能找到左边第一个比当前柱子高的柱子
  • 每次遇到更高的柱子时，就能确定一个凹槽的边界，从而计算出该凹槽能接的雨水量

LC 11 盛最多水的容器 9次

题目链接：LC 11 盛最多水的容器

题目描述

给定一个长度为 n 的整数数组 height 。有 n 条垂线，第 i 条线的两个端点是 (i, 0) 和 (i, height[i]) 。

找出其中的两条线，使得它们与 x 轴共同构成的容器可以容纳最多的水。

返回容器可以储存的最大水量。

说明：你不能倾斜容器。

示例 1：

输入：[1,8,6,2,5,4,8,3,7]
输出：49
解释：图中垂直线代表输入数组 [1,8,6,2,5,4,8,3,7]。在此情况下，容器能够容纳水（表示为蓝色部分）的最大值为 49。

示例 2：

输入：height = [1,1]
输出：1

提示：

n == height.length
2 <= n <= 10^5
0 <= height[i] <= 10^4

ACM完整代码

思路及必要说明

这是一道经典的双指针题目，核心思想是利用左右指针从两端向中间移动，寻找能容纳最多水的容器。

关键观察：

  • 容器的容量 = 宽度 × 高度 = (右指针 - 左指针) × min(左高度, 右高度)
  • 宽度随着指针移动会减小，要想获得更大容量，必须找到更高的高度

双指针策略：

  1. 初始化：左指针在数组起点，右指针在数组终点
  2. 计算当前容量：计算当前指针位置形成的容器容量，并更新最大值
  3. 移动指针：移动高度较小的那一侧的指针
    • 如果左高度 < 右高度，移动左指针（因为移动右指针只会让宽度变小，而高度由左高度决定，不可能变大）
    • 否则移动右指针

为什么这样做是正确的？

  • 假设 height[left] < height[right]，此时以 left 为左边界的最大容量已经找到了（因为高度由 left 决定，宽度已经最大）
  • 所以应该移动 left 指针，寻找可能更高的高度
  • 反之亦然

时间复杂度：O(n)，只需一次遍历
空间复杂度：O(1)，只使用常量空间

LC 15 三数之和 9次

题目链接：LC 15 三数之和

题目描述

给你一个整数数组 nums ，判断是否存在三元组 [nums[i], nums[j], nums[k]] 满足 i != j、i != k 且 j != k ，同时还满足 nums[i] + nums[j] + nums[k] == 0 。请你返回所有和为 0 且不重复的三元组。

注意：答案中不可以包含重复的三元组。

示例 1：

输入：nums = [-1,0,1,2,-1,-4]
输出：[ [-1,-1,2],[-1,0,1]]
解释：
nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0 。
nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0 。
nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0 。
不同的三元组是 [-1,0,1] 和 [-1,-1,2] 。
注意，输出的顺序和三元组的顺序并不重要。

示例 2：

输入：nums = [0,1,1]
输出：[]
解释：唯一可能的三元组和不为 0 。

示例 3：

输入：nums = [0,0,0]
输出：[[0,0,0] ]
解释：唯一可能的三元组和为 0 。

提示：

3 <= nums.length <= 3000
-10^5 <= nums[i] <= 10^5

思路及必要说明

这是一道经典的双指针题目，核心思想是先排序，然后固定第一个元素，用双指针寻找另外两个元素使得三数之和为0。

关键观察：

  • 需要找到所有不重复的三元组，所以需要排序来方便去重
  • 固定一个元素后，问题转化为两数之和问题，可以用双指针高效解决

解题步骤：

  1. 排序数组：排序后方便去重和双指针操作
  2. 遍历第一个元素：固定第一个元素 nums[i]
  3. 双指针寻找另外两个元素：
    • 左指针 j = i + 1，右指针 k = n - 1
    • 如果 nums[i] + nums[j] + nums[k] == 0，找到一个解
    • 如果和小于0，移动左指针增大和
    • 如果和大于0，移动右指针减小和
  4. 去重处理：
    • 跳过相同的第一个元素
    • 找到解后，跳过相同的左指针和右指针元素

优化策略：

  • 如果第一个元素已经大于0，直接break（三数之和不可能为0）
  • 如果第一个元素加上后两个最小元素仍大于0，break
  • 如果第一个元素加上后两个最大元素仍小于0，continue

时间复杂度：O(n²)，排序O(n log n)，双指针遍历O(n²)
空间复杂度：O(log n) 或 O(n)，取决于排序算法的空间复杂度

思路及必要说明

这是一道经典的滑动窗口题目，核心思想是维护一个窗口，当窗口内元素和大于等于target时，尝试缩小窗口找到最小长度。

关键观察：

  • 数组中的元素都是正整数，这意味着当窗口向右扩展时，窗口内元素的和是单调递增的
  • 因此可以使用滑动窗口来高效找到满足条件的最小长度

滑动窗口策略：

  1. 右指针扩展窗口：不断向右移动右指针，将元素加入窗口并累加和
  2. 左指针收缩窗口：当窗口内元素和 >= target 时，尝试移动左指针缩小窗口
  3. 更新最小长度：每次收缩窗口时，更新满足条件的最小窗口长度

具体实现：

  • 使用 left 和 right 两个指针表示窗口的左右边界
  • s 记录当前窗口内元素的和
  • 右指针每次移动时，将当前元素加入 s
  • 当 s >= target 时，更新最小长度，并尝试移动左指针减小窗口
  • 最后如果最小长度仍为初始值（n+1），说明没有找到满足条件的子数组，返回0

时间复杂度：O(n)，每个元素最多被访问两次（一次加入窗口，一次移出窗口）
空间复杂度：O(1)，只使用常量空间

进阶思路（O(n log n)）：

  • 可以使用前缀和 + 二分查找的方法
  • 前缀和数组是单调递增的，可以对每个右边界二分查找左边界

LC 142 环形链表II 7次

题目链接：LC 142 环形链表II

题目描述

给定一个链表的头节点 head ，返回链表开始入环的第一个节点。 如果链表无环，则返回 null。

示例 1：

输入：head = [3,2,0,-4], pos = 1
输出：返回索引为 1 的链表节点
解释：链表中有一个环，其尾部连接到第二个节点。

示例 2：

输入：head = [1,2], pos = 0
输出：返回索引为 0 的链表节点
解释：链表中有一个环，其尾部连接到第一个节点。

示例 3：

输入：head = [1], pos = -1
输出：返回 null
解释：链表中没有环。

提示：

链表中节点的数目范围在范围 [0, 10^4] 内
-10^5 <= Node.val <= 10^5
pos 的值为 -1 或者链表中的一个有效索引

进阶：你是否可以使用 O(1) 空间解决此题？

思路及必要说明

这是一道经典的快慢指针（Floyd判圈算法）题目，核心思想是利用快慢指针检测环并找到环的入口。

关键观察：

  • 如果链表有环，快慢指针最终会相遇
  • 相遇后，将其中一个指针移到链表头部，然后两个指针以相同速度移动，再次相遇时就是环的入口

算法步骤：

  1. 检测环：使用快慢指针，快指针每次移动两步，慢指针每次移动一步
    • 如果快指针到达尾部（null或null.next），说明无环
    • 如果快慢指针相遇，说明有环
  2. 找到环的入口：
    • 将慢指针（或快指针）移到链表头部
    • 两个指针以相同速度移动（每次一步）
    • 再次相遇时，就是环的入口

数学证明：
设链表头部到环入口的距离为a，环入口到相遇点的距离为b，环的长度为c

  • 相遇时，慢指针走了 a + b 步
  • 快指针走了 a + b + kc 步（k为绕环圈数）
  • 因为快指针速度是慢指针的两倍：2(a + b) = a + b + kc => a + b = kc => a = kc - b
  • 所以从相遇点再走a步就能到达环入口，而从头部走a步也能到达环入口

时间复杂度：O(n)，最多遍历两次链表
空间复杂度：O(1)，只使用常量空间

LC 239 滑动窗口最大值 5次

题目链接：LC 239 滑动窗口最大值

题目描述

给你一个整数数组 nums，有一个大小为 k 的滑动窗口从数组的最左侧移动到数组的最右侧。你只可以看到在滑动窗口内的 k 个数字。滑动窗口每次只向右移动一位。

返回 滑动窗口中的最大值 。

示例 1：

输入：nums = [1,3,-1,-3,5,3,6,7], k = 3
输出：[3,3,5,5,6,7]
解释：

滑动窗口的位置 最大值
[1 3 -1] -3 5 3 6 7 3
1 [3 -1 -3] 5 3 6 7 3
1 3 [-1 -3 5] 3 6 7 5
1 3 -1 [-3 5 3] 6 7 5
1 3 -1 -3 [5 3 6] 7 6
1 3 -1 -3 5 [3 6 7] 7

示例 2：

输入：nums = [1], k = 1
输出：[1]

提示：

1 <= nums.length <= 10^5
-10^4 <= nums[i] <= 10^4
1 <= k <= nums.length

ACM模式完整代码

思路及必要说明

这是一道经典的滑动窗口题目，核心思想是使用双端队列（单调队列）来维护窗口内的最大值。

关键观察：

  • 滑动窗口每次向右移动一位，需要快速获取窗口内的最大值
  • 如果暴力遍历每个窗口，时间复杂度为O(nk)，对于大数组会超时
  • 需要一个数据结构来高效维护窗口内的最大值

单调队列策略：

  1. 维护单调递减队列：队列中存储的是数组下标，对应的数组值从队首到队尾单调递减
  2. 新元素入队：
    • 从队尾开始，移除所有小于等于当前元素的下标
    • 将当前元素的下标加入队尾
  3. 移除过期元素：如果队首元素的下标已经不在当前窗口内，移除队首
  4. 记录窗口最大值：队首元素对应的数组值就是当前窗口的最大值

具体实现：

  • 使用 deque 双端队列存储下标
  • 遍历数组，对于每个位置 i：
    • 从队尾移除所有 nums[q.back()] <= nums[i] 的元素（它们不可能成为后续窗口的最大值）
    • 将 i 加入队尾
    • 如果队首元素 < i - k + 1（窗口左边界），移除队首
    • 当 i >= k - 1 时，队首就是当前窗口的最大值

时间复杂度：O(n)，每个元素最多入队和出队一次
空间复杂度：O(k)，队列最多存储k个元素

为什么这样做是正确的？

  • 队列始终保持单调递减，队首永远是窗口内最大元素的下标
  • 移除比当前元素小的元素是安全的，因为它们不可能在后续窗口中成为最大值
  • 维护队列中的下标而不是值，可以方便判断元素是否在窗口内
