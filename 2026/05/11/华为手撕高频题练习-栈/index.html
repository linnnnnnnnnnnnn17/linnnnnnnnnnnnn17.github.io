思路及必要说明

这是一道经典的栈应用题目，核心是利用栈来匹配括号的正确性。

关键观察：

  • 有效字符串的长度必须是偶数
  • 右括号必须与最近的左括号匹配，且类型相同
  • 栈可以很好地处理这种嵌套结构

算法策略：

  1. 初始化检查：如果字符串长度为奇数，直接返回false
  2. 遍历字符串：
    • 遇到左括号，将对应的右括号压入栈
    • 遇到右括号，检查栈是否为空或栈顶是否匹配
  3. 匹配检查：
    • 如果栈为空或栈顶不匹配当前右括号，返回false
    • 否则弹出栈顶
  4. 最终检查：遍历结束后，栈必须为空

时间复杂度：O(n)，每个字符最多入栈和出栈一次
空间复杂度：O(n)，最坏情况下栈存储所有字符

实现技巧：

  • 可以使用哈希表存储括号映射关系（如 {'(':')', '[':']', '{':'}'}）
  • 也可以直接在代码中判断，避免哈希表查找开销

思路及必要说明

这是一道经典的栈应用题目，核心是利用栈来处理嵌套的字符串解码。

关键观察：

  • 编码规则为 k[encoded_string]，表示方括号内的字符串重复k次
  • 嵌套结构适合用栈来处理，遇到 [ 时保存当前状态，遇到 ] 时恢复状态
  • 数字可能是多位数（如 “10[abc]”）

算法策略：

  1. 遍历字符串：
    • 遇到字母：直接添加到当前结果字符串
    • 遇到数字：累积计算完整的数字值
    • 遇到 [：将当前结果字符串和数字压入栈，然后重置
    • 遇到 ]：弹出栈顶的字符串和数字，将当前结果重复指定次数后拼接到弹出的字符串后

栈的作用：

  • 存储进入 [...] 之前的状态（当前字符串和重复次数）
  • 遇到 ] 时恢复之前的状态，实现类似递归的效果

时间复杂度：O(n)，每个字符最多被处理几次（取决于重复次数，但摊还分析为O(n)）
空间复杂度：O(n)，栈存储的状态信息

实现技巧：

  • 使用 move 语义优化字符串操作，避免不必要的拷贝
  • 注意数字可能是多位数，需要累积计算

关于 std::move() 的详细说明：

  • move 是 C++11 引入的右值引用特性，用于实现移动语义
  • 在代码中 stk.emplace(move(res), k) 和 res = move(pre_res) 使用了 move
  • 作用：将 res 的所有权转移给栈中的 pair，而不是复制字符串
  • 性能提升：对于长字符串，复制操作是 O(n)，而移动操作是 O(1)，只是转移指针
  • 使用场景：当确定不再需要原变量时，使用 move 避免深拷贝
  • 注意事项：move 后原变量处于有效但未定义状态，不应再使用

思路及必要说明

这是一道经典的单调栈题目，核心是利用单调栈来寻找每个元素右边第一个更大的元素。

关键观察：

  • 需要找到每个位置之后第一个比它大的元素的位置
  • 单调栈可以在O(n)时间内解决这类”下一个更大元素”问题
  • 栈中存储的是数组下标，保持对应的值单调递减

算法策略：

  1. 维护单调递减栈：栈中存储的是数组下标，对应的温度值从栈底到栈顶单调递减
  2. 遍历每个温度：
    • 如果当前温度 > 栈顶温度，说明找到了栈顶元素的下一个更高温度
    • 弹出栈顶元素，计算距离并记录结果
    • 重复上述过程直到栈为空或栈顶温度 >= 当前温度
    • 将当前下标压入栈
  3. 未找到更高温度的元素：栈中剩余元素对应的结果保持为0

单调栈的作用：

  • 维护一个递减序列，确保每次遇到更大的元素时能找到所有需要更新的位置
  • 每个元素最多入栈和出栈一次

时间复杂度：O(n)，每个元素最多入栈和出栈一次
空间复杂度：O(n)，栈的最大深度

为什么这样做是正确的？

  • 栈中始终保持递减顺序，所以当遇到更大的元素时，栈顶元素的下一个更大元素就是当前元素
  • 弹出栈顶后继续检查新的栈顶，直到栈为空或栈顶元素更大

思路及必要说明

这是一道经典的栈设计题目，核心是在常数时间内获取栈中的最小元素。

关键观察：

  • 普通栈只能在O(1)时间内获取栈顶元素，但无法快速获取最小值
  • 需要维护额外的信息来跟踪最小值

算法策略：

  1. 使用栈存储成对元素：每个栈元素存储 (当前值, 当前最小值)
  2. push操作：
    • 新元素的值与当前最小值比较
    • 存储 (val, min(current_min, val))
  3. pop操作：直接弹出栈顶元素
  4. top操作：返回栈顶元素的第一个值
  5. getMin操作：返回栈顶元素的第二个值

哨兵节点优化：

  • 在栈底添加一个哨兵节点 (0, INT_MAX)，避免空栈判断
  • 这样 getMin() 可以直接返回 ms.top().second

时间复杂度：O(1)，所有操作都是常数时间
空间复杂度：O(n)，需要存储额外的最小值信息

实现技巧：

  • 使用 emplace 直接构造pair，避免拷贝
  • 哨兵节点简化了边界条件处理

关于 emplace() 的详细说明：

  • emplace 是 C++11 引入的方法，用于在容器中直接构造对象
  • 与普通 push 的区别：
    • push：先构造对象，再复制/移动到容器中
    • emplace：直接在容器内存位置构造对象，避免额外的拷贝/移动
  • 代码示例对比：
  • 性能优势：对于复杂对象，可以减少一次构造和一次拷贝/移动
  • 使用建议：C++11 后优先使用 emplace 系列方法

priority_queue 三个模板参数到底是什么

完整原型：

三个参数依次是：

  1. T：存什么类型（int、pair、结构体）
  2. Container：底层用什么容器存（默认 vector）
  3. Compare：比较规则，决定是大顶堆还是小顶堆

为什么默认是大顶堆？

默认第三个参数：less<int>

  • less<int>：a < b，把大的放前面 → 大顶堆
你写小顶堆必须改成：greater<int>

最关键：比较函数逻辑和你直觉相反！

priority_queue 内部规则：

返回 true：第一个元素放下面，第二个放上面

1. 默认 less（大顶堆）
less<int>() 是 a < b

  • 如果 a < b → 返回 true → b 放上面
    → 大的在上 → 大顶堆

2. greater（小顶堆）
greater<int>() 是 a > b

  • 如果 a > b → 返回 true → b 放上面
    → 小的在上 → 小顶堆

通俗大白话

  • less：谁大谁在上（大顶堆）
  • greater：谁小谁在上（小顶堆）

所以小顶堆必须完整写三个参数：

不能省略，因为要改第三个参数，前面两个必须带上。

  • 大顶堆：priority_queue<int>
  • 小顶堆：priority_queue<int,vector<int>,greater<int>>
  • less→大顶，greater→小顶，逻辑反着来

优先队列（Priority Queue）介绍：

  • 优先队列是一种特殊的队列，元素按照优先级排序，而不是先进先出
  • C++ 中的 priority_queue 默认是大顶堆（最大元素在队首）
  • 通过自定义比较函数，可以实现小顶堆（最小元素在队首）
  • 核心操作：
    • push(x)：将元素 x 加入堆，时间复杂度 O(log n)
    • pop()：移除堆顶元素，时间复杂度 O(log n)
    • top()：获取堆顶元素，时间复杂度 O(1)
    • empty()：判断堆是否为空，时间复杂度 O(1)

本题中优先队列的使用：

  • 比较函数逻辑：return a->val > b->val 表示当 a 的值大于 b 的值时，a 的优先级更低，应该排在 b 后面
  • 这样堆顶始终是值最小的节点

算法策略：

  1. 构建最小堆：使用优先队列存储所有非空链表的头节点
  2. 初始化堆：将每个链表的头节点（非空）加入堆
  3. 合并过程：
    • 取出堆顶元素（最小节点），加入结果链表
    • 如果该节点还有下一个节点，将其加入堆
    • 重复直到堆为空
  4. 哨兵节点：使用哨兵节点简化链表操作

堆的作用：

  • 高效维护k个链表的当前最小节点
  • 每次操作的时间复杂度为O(log k)

时间复杂度：O(N log k)，N是所有节点总数，每次堆操作O(log k)
空间复杂度：O(k)，堆最多存储k个节点

输入输出处理：

  • 输入格式：[[1,4,5],[1,3,4],[2,6]]
  • 输出格式：[1,1,2,3,4,4,5,6]
  • 需要解析嵌套的方括号结构，转换为链表数组
  • 需要将结果链表转换为字符串输出
