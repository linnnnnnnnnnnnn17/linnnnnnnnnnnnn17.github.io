一、equals 与 hashCode（3 场被问）⭐⭐⭐

1.0 hashCode 是什么

hashCode：对象的哈希码，一个 int 类型的整数。

作用：用于 HashMap、HashSet 等哈希表快速定位对象。

默认实现：

  • Object 类的 hashCode() 方法根据内存地址计算
  • 不同对象通常有不同的 hashCode
  • equals 为 true 的对象，hashCode 必须相等

1.1 为什么重写 equals 必须同时重写 hashCode

原因：保证集合一致性

问题：

  • equals 比较的是内容，p1 和 p2 内容相同
  • hashCode 如果不重写，比较的是内存地址
  • 两个对象 hashCode 不同，HashMap 会认为是不同 key

规则：

  • 如果两个对象 equals 相等，则 hashCode 必须相等
  • 如果两个对象 hashCode 相等，equals 不一定相等

1.2 自定义对象做 HashMap 的 key 要注意什么

  1. 必须重写 equals 和 hashCode
  2. key 应该不可变：字段不能修改（不要用可变对象做 key）
  3. 建议重写 toString（方便调试）

1.3 手写 equals 和 hashCode

hashCode 计算公式：

  • result = 31 * result + field.hashCode()
  • 31 是质数，乘积分布均匀

2.1 HashMap 工作原理和哈希冲突

底层数据结构：数组 + 链表 + 红黑树（JDK 8+）

哈希冲突：不同 key 得到相同下标

解决方式：

  1. 链表：冲突的元素串成链表
  2. 红黑树：链表长度 > 8 转为红黑树

2.1.1 红黑树介绍

红黑树（Red-Black Tree）：自平衡的二叉搜索树

特点：

  • 每个节点非红即黑
  • 根节点是黑色
  • 叶子节点（NIL）是黑色
  • 红节点的子节点必须是黑色
  • 每个节点到叶子节点路径黑色节点数相同

优点：

  • 自动平衡，查找/插入/删除 O(logN)
  • 比平衡二叉树（如 AVL）插入删除开销小

应用场景：

  • TreeMap、TreeSet 底层
  • HashMap 链表冲突时（链表 > 8 转红黑树）
  • Java 8+ HashMap

2.2 HashMap 和 LinkedHashMap 的区别

特性 HashMap LinkedHashMap
顺序 无序 插入顺序
结构 数组+链表+红黑树 HashMap + 双向链表
性能 更高 稍低（维护链表）
迭代 无序 有序

2.3 ArrayList 和 LinkedList 的区别

特性 ArrayList LinkedList
底层 数组 双向链表
查询 O(1)，快 O(n)，慢
插入/删除 O(n)，需移动 O(1)，只需修改指针
内存 连续，节省 每个节点存指针
适用场景 查询多 增删多

实现类 底层结构 特点 线程安全

Vector 数组 同 ArrayList 是

实现类 底层结构 特点 线程安全

Map（键值对）

实现类 底层结构 特点 线程安全

TreeMap 红黑树 自动按 key 排序 否

线程安全是什么

线程安全：多个线程同时访问同一个资源，不会产生数据错误。

为什么需要线程安全：

  • 多线程共享数据
  • 避免数据竞争（race condition）
  • 保证数据一致性

线程安全集合

实现类 特点
Vector 同步方法，效率低（古老）
Hashtable 同步方法，效率低（古老）
Collections.synchronizedXxx() 同步包装，性能一般
ConcurrentHashMap 分段锁，高并发推荐
CopyOnWriteArrayList 读多写少，COW 策略
BlockingQueue 阻塞队列，生产者-消费者模式
