1. TCP/UDP 及可靠传输（3 场被问）⭐⭐⭐

TCP 和 UDP 的区别

特性 TCP UDP
连接 面向连接（三次握手） 无连接
可靠性 可靠（确认、重传、排序） 不可靠
传输方式 字节流 数据报
头部大小 20-60 字节 8 字节
速度 慢 快
资源占用 高 低
顺序 保证有序 不保证
流量控制 滑动窗口 无
拥塞控制 有（慢启动、拥塞避免） 无

应用场景

TCP 适用场景：

  • 需要可靠传输：文件传输、HTTP、HTTPS、邮件
  • 顺序重要：数据传输、远程控制
  • 重要数据：支付、登录

UDP 适用场景：

  • 实时性要求高：视频流、语音通话、直播
  • 对可靠性要求不高：DNS、SNMP
  • 广播/多播场景
  • 简单查询：RPC、MQTT

TCP 如何保证可靠传输？

1. 三次握手建立连接

为什么需要三次？

  • 防止失效的连接请求被服务器接受
  • 双方确认彼此的序列号

2. 四次挥手断开连接

为什么需要四次？

  • 双方都要确认自己发送完毕
  • 2MSL 确保最后一个 ACK 到达

3. HTTP 相关（2 场被问）⭐⭐

301 和 302 的区别

特性 301 Moved Permanently 302 Found
含义 永久重定向 临时重定向
搜索引擎 传递权重（SEO 好） 不传递权重
浏览器缓存 会缓存 通常不缓存
适用场景 域名更换、HTTP→HTTPS 负载切换、A/B 测试
HTTP 方法 永久改变 临时改变

HTTP 请求方法

方法 含义 幂等 安全性 典型用途
GET 获取资源 ✅ ✅ 读取数据
POST 创建资源 ❌ ❌ 提交表单
PUT 替换资源 ✅ ❌ 更新数据
DELETE 删除资源 ✅ ❌ 删除数据
PATCH 部分更新 ❌ ❌ 局部更新
HEAD 获取头部 ✅ ✅ 仅检查资源
OPTIONS 查询支持的方法 ✅ ✅ CORS 预检
