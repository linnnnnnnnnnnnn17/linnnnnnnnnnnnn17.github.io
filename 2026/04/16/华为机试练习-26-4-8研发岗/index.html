REALHW153 魔导数据包的混合进制编码

描述

小红正在术式终端前维护城市结界的能耗监控系统。为了压缩传输过程中的冗余数据，她需要对一个魔力值整数 n 进行“混合进制编码”处理。
具体编码规程如下：

  1. 符号位确定：首先根据 n 的正负号确定编码序列的第一个数字 s。若 n < 0，则 s = 1；若 n ≧ 0，则 s = 0。
  2. 进制分解：取 q =∣n∣（n 的绝对值）。给定一个包含 m 个正整数的进制序列 b1, b2,…,bm。按照序列顺序，对 q 依次进行如下操作：
    对于每个 bi​，当前位的编码数字 di =q mod bi，随后更新 q = ⌊q/bi⌋。
  3. 字符映射：将得到的数字序列 (s, d1, d2, …, dm) 按顺序映射为小写字母，映射规则为 0 → ’a’, 1 → ’b’, …, 25 → ’z’。将这些字母拼接，得到最终的编码字符串 S。
  4. 回文校验与提取：
  • 若 S 本身是一个回文字符串，则输出 S 并在其后紧跟后缀 (palindrome)。
  • 若 S 不是回文字符串，则需要提取 S 中长度最长的回文子串；若存在多个长度相等的最长回文子串，则输出其中字典序最小的一个。

输入描述：

输入包含两行。
第一行一个整数 n（−10^6 ≦ n ≦ 10^6 ），代表待编码的魔力值。
第二行包含若干个以空格分隔的整数，表示进制序列 b1, b2, …, bm（1 ≦ m ≦ 10, 2 ≦ bi ≦26）。

输出描述：

输出一个字符串，表示按规程处理后的编码结果。

示例1

输入：
-21
5 7 3
输出：
bb

cin.ignore() 的作用

在华为机试的ACM模式中，输入分为多行：

  • 第一行：整数 n
  • 第二行：若干个以空格分隔的整数 b1, b2, …, bm

读取完 n 后，输入缓冲区中会遗留一个换行符 \n（即回车键）。如果直接用 while (cin >> b) 读取第二行数字，while 条件会因为这个换行符而立即失败，导致无法读取后续数据。

cin.ignore() 的作用正是忽略（丢弃）输入缓冲区中的第一个字符，从而清除换行符，使得后续的 cin >> b 能正常读取第二行的数据。

更精确的写法也可以用 cin.ignore(numeric_limits<streamsize>::max(), '\n')，表示忽略直到遇到换行符的所有字符，但在本题中只需忽略一个字符即可。

中心扩展法求最长回文子串

回文串的特征是对称：无论是奇数长度（如 “aba”）还是偶数长度（如 “abba”），都可以选择一个中心点向两侧扩展。

核心思路：

  • 枚举每个可能的中心点，向左右两侧同时扩展
  • 每次扩展时检查左右字符是否相等，若相等则继续扩展，否则停止
  • 记录每次扩展得到的回文串长度，取最长的；若长度相同则取字典序最小的

为什么遍历 2*n-1 个中心？

  • 长度为 n 的字符串有 n 个单字符中心（奇数回文如 “aba”）
  • 同时还有 n-1 个两字符间隙中心（偶数回文如 “abba”）
  • 共 2n-1 种情况，覆盖了所有可能的回文

代码解析：

  • 当 i 为偶数（如 0,2,4）时，l == r，从单字符中心扩展（奇数长度）
  • 当 i 为奇数（如 1,3,5）时，l + 1 == r，从两字符间隙扩展（偶数长度）

REALHW154 魔导模块的效能迭代

描述

小红正在术式终端上维护一套由 n 个魔导模块构成的核心系统。每个模块 i 在运行时的执行耗时为 a[i]。根据术士协会的规程，每个模块都有一个性能下限 b[i] ，即该模块的执行耗时无论如何优化都不能低于 b[i]。
小红计划在接下来的 m 天内，每天对其中一个模块进行一次效能迭代。如果选中的模块当前耗时为 t，经过一次迭代后，其新耗时将变为 max(⌈t/2⌉,b[i])。其中 ⌈x⌉ 表示对 x 向上取整。
请问在 m 天的优化结束后，所有模块的执行耗时之和最小是多少？

输入描述：

第一行包含两个整数 n 和 m (1 ≦ n ≦ 1000, 0 ≦ m ≦ 1000)，分别表示模块的数量和优化的总天数。
第二行包含 n 个整数 a[1], a[2], …, a[n] (1 ≦ a[i] ≦10^5)，表示各模块的初始执行耗时。
第三行包含 n 个整数 b[1], b[2], …, b[n] (1 ≦ b[i] ≦a[i] ≦10^5)，表示各模块允许的执行耗时下限。

输出描述：

输出一个整数，表示 m 天后所有模块执行耗时之和的最小值。

示例1

输入：
2 3
100 80
40 10

输出：
70

说明：

在样例中，n=2,m=3：

- 第 1 天：优化模块 1，其耗时从 100 变为 max(⌈100/2⌉,40)=50。

- 第 2 天：优化模块 2，其耗时从 80 变为 max(⌈80/2⌉,10)=40。

- 第 3 天：再次优化模块 2，其耗时从 40 变为 max(⌈40/2⌉,10)=20。

最终各模块的耗时分别为 50 和 20，总和为 50+20=70。此时总和达到最小。

思路及必要说明

算法思想：贪心算法

本题要求在 m 天内每天选择一个模块进行优化，使最终所有模块耗时之和最小。代码采用了贪心算法策略。

核心思路

每次迭代时，遍历所有模块，计算对每个模块进行一次优化所能减少的耗时量，选择减少量最大的模块进行优化。重复 m 次，即得到最优解。

关键计算

对于模块 j，假设当前耗时为 a[j]，下限为 b[j]，优化后的耗时为 max(ceil(a[j]/2), b[j])。

由于 a[j] 为整数，ceil(a[j]/2) 等价于 (a[j] + 1) / 2（整数除法向上取整），但在代码中直接使用 a[j] / 2（向下取整）配合后续判断：

  • 情况一：a[j]/2 >= b[j]

    • 优化后新耗时为 a[j]/2
    • 本次优化减少量为 a[j] - a[j]/2 = a[j]/2

  • 情况二：a[j]/2 < b[j]

    • 优化后新耗时为 b[j]（已达到下限，无法再降）
    • 本次优化减少量为 a[j] - b[j]

代码中的 c 变量即表示本次优化的减少量。每次选择 c 值最大的模块进行优化，即可保证全局最优。

时间复杂度

外层循环 m 次，内层遍历 n 个模块，时间复杂度为 **O(m × n)**，在题目约束（n, m ≤ 1000）下完全满足要求。

REALHW155 术式终端的并行调度

描述

小红正在术士协会的实训室里调试一套魔导调度系统。这套系统由若干台规格相同的核心服务器组成，每台服务器都拥有固定的 CPU 算力上限 C 和内存容量上限 M。
小红手头共有 n 个待运行的术式任务。对于第 i 个任务，它需要消耗 c[i] 单位的算力、消耗 m[i] 单位的内存，并在运行成功后产生 v[i] 单位的术式价值。对于每一台独立的服务器，在其上运行的任务集合 S 必须严格满足以下约束：

  1. 任务的算力消耗总和不得超过服务器上限，即 ∑ i∈S c[i] ≦C。
  2. 任务的内存消耗总和不得超过服务器上限，即 ∑ i∈S m[i] ≦M。
    现在，小红希望分别计算：当她拥有 1,2,…,n 台服务器时，通过合理分配任务到各台服务器上，所能获得的任务总价值最大分别是多少？

输入描述：

输入仅包含一组测试数据。
第一行包含三个整数 n,C,M (1≦n≦15,1≦C,M≦10^6)，分别代表任务的总数、单台服务器的 CPU 算力上限以及内存容量上限。
接下来 n 行，每行包含三个整数 c[i], m[i], v[i] (1≦c[i], m[i], v[i] ≦10^6)，分别表示第 i 个术式任务的算力需求、内存需求及产生的价值。

输出描述：

输出共 n 行。
第 i 行（1≦i≦n）输出一个整数，表示在使用 i 台服务器的情况下，所能获得的最大任务总价值。

示例1

输入：
3 3 10
1 4 1
2 5 2
2 6 4

输出：
5
7
7

说明：

当拥有 k=1 台服务器时：小红可以选择运行第 1 个和第 3 个任务。总算力消耗为 1+2=3≦3，总内存消耗为 4+6=10≦10，此时获得最大价值 1+4=5。

当拥有 k=2 台服务器时：第一台服务器运行任务 1 和 3，第二台服务器运行任务 2。总价值为 1+4+2=7。

当拥有 k=3 台服务器时：由于 2 台服务器已经可以运行全部任务，第 3 台服务器会保持空闲，最大价值仍为 7。

ACM模式完整代码

思路及必要说明

算法思想：状态压缩 + 资源约束检查

本题 n ≤ 15，任务数量较小，可以采用状态压缩枚举的思想：枚举所有可能的任务分配方案，检查是否满足资源约束。

核心思路

  1. 枚举任务子集：共有 2^n 种任务选择方案（n ≤ 15，最多 32768 种）
  2. 计算子集属性：对每个子集，计算其总算力消耗 sum_c、总内存消耗 sum_m、总价值 sum_v
  3. 检查资源约束：对于每个服务器数量 k（1 到 n），如果 sum_c ≤ k*C 且 sum_m ≤ k*M，说明该任务子集可以在 k 台服务器上运行，更新答案为较大值
  4. 取最优：遍历完所有子集后，ans[k] 即为 k 台服务器的最大价值

代码解析

  • state 的二进制表示中第 i 位为 1 表示选择第 i 个任务
  • 外层循环枚举所有 2^n 种任务选择
  • 内层对每个 k 检查资源约束是否满足
  • 取所有满足条件的最大价值

时间复杂度

  • 枚举子集：O(2^n × n)
  • 对每个子集检查 n 个 k 值：O(2^n × n)
  • 总时间复杂度：O(n × 2^n)，约 15 × 32768 ≈ 50 万次操作，完全满足要求

关键洞察

为什么不需要考虑”任务不重复”的问题？
因为我们是枚举所有任务子集——每个子集代表一种任务选择方案。当检查 sum_c ≤ k*C 时，相当于假设这 k 台服务器可以共同运行这些任务。由于每台服务器的资源独立，总资源就是 k×C 和 k×M，这种检查方式已经涵盖了所有可能的分配情况。
