一、为什么会出现「烫烫烫烫」？

这是 Windows 调试模式下未初始化的栈内存 的典型表现 ✅

在 Visual Studio 的 Debug 配置下：

  • 编译器会自动把未初始化的栈内存填充为 0xCC
  • 0xCC 在 GB2312/GBK 编码下，正好对应汉字 「烫」
  • 所以当你打印/查看一段未初始化的字符数组时，就会看到满屏的「烫烫烫」

从代码和调试窗口可以看到，你的 NameReader 类存在一个字符串结束符缺失的问题，这会导致后续输出时出现乱码：

💡 补充说明

  • **为什么要加 \0**：C 风格字符串以 \0 作为结束标志，没有它的话，函数（如 strlen、cout）会一直向后读取内存，直到遇到随机的 0，导致乱码或崩溃。

  • 最佳实践：尽量使用 std::string 替代原生字符数组，它会自动管理内存和结束符，从根源避免这类问题。

🧩 为什么调试器还显示「烫烫烫」？

  1. 断点位置问题：你现在停在 readName() 刚执行 std::cout 的位置，**memset 初始化已经完成**，但还没执行到输入名字和拷贝的步骤。
  2. 调试器的显示规则：
    • 你的 m_name 已经被 memset 初始化为全 0（即 \0），这是一个合法的空字符串。
    • 但 Visual Studio 调试器在查看 char[] 类型时，会尝试将内存解析为 GBK 编码字符串。
    • 当字符串为空（全是 \0）时，调试器会向后越界读取栈内存，而这块未使用的栈内存恰好被 Debug 模式填充为 0xCC，也就是「烫」字。
  3. 关键证据：展开 m_name 看 m_name[0] 的值，它是 0 或 '\0'，这就证明初始化完全成功。

  • 构造函数：memset(m_name, 0, sizeof(m_name)); 已经把数组清空为 \0。
