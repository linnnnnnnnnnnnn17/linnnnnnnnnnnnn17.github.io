REALHW132 魔法相册的重复记忆

题目链接：REALHW132 魔法相册的重复记忆

描述

小红正在整理自己的 n 本魔法相册，她发现有些珍贵的记忆（照片）由于备份原因，同时出现在了多本相册中。
每张照片由一个唯一的标识符 id 和一个时间戳 t 组成。在一个相册内部，所有照片的 id 互不相同；但在不同的相册之间，可能存在 id 相同的照片。已知相同的 id 总是对应相同的时间戳 t。
小红需要找出所有在超过一本相册中出现过的照片，并统计它们在所有相册中出现的总次数。请将这些重复的照片按照时间戳 t 从小到大排序后输出。

输入描述：

第一行输入一个整数 n（0 < n < 10），表示相册的数量。
接下来的 n 行，每行包含若干个由空格分隔的整数，表示该相册内的照片信息。每两个整数为一个组合，前一个为照片的 id，后一个为该照片的时间戳 t。
每行照片的数量 m 满足 0 < m < 100。所有 id 和 t 均为非负整数。

输出描述：

输出一行整数，每两个整数为一个组合，分别为重复出现的照片 id 及其在所有相册中出现的总次数。
组合之间按时间戳 t 升序排列。输入保证至少存在一张重复的照片，且排序结果唯一。

示例1

输入：
4
999 1 998 2 997 3 996 4 995 5
994 6 993 7 992 8 991 9 990 10
989 11 988 12 987 13
999 1 995 5 986 14

输出：
999 2 995 2

说明：

样例说明：

- 照片 id 为 999 的时间戳为 1，在第 1 本和第 4 本相册中出现，总次数为 2。

- 照片 id 为 995 的时间戳为 5，在第 1 本和第 4 本相册中出现，总次数为 2。

- 其余照片均只出现了一次。

- 按照时间戳排序，1<5，故先输出 999 2，再输出 995 2。

思路及必要说明

本题思路

用结构体把 id 和 t 封装到 photo 里，用 unordered_map 记录出现次数，再转成 vector 按 t 排序，最后输出出现次数大于 1 的。

关键难点

  1. unordered_map 的 key 是自定义 struct 需要重载 == 和手写哈希函数
  2. unordered_map 不能直接排序，要转成 vector

unordered_map的key是自定义struct怎么处理

可以，但必须手动满足两个条件，否则直接编译报错：

  1. 提供哈希函数（std::hash 特化 / 自定义哈希）
  2. 提供相等比较运算符 ==

一、为什么普通结构体不能直接当 key

unordered_map 底层是哈希表：

  • 插入/查找：先对 key 算哈希值
  • 冲突时：用 == 判断元素是否相等

C++ 标准库没有默认提供：

  • 自定义结构体的 std::hash 哈希实现
  • 所以直接写会报错：no specialization of std::hash

二、完整可运行写法（两种常用方案）

方案1：重载 == + 特化 std::hash（推荐）
方案2：传入自定义哈希+判等（不污染std命名空间）

三、补充区分：map 和 unordered_map

  1. std::map<结构体, T>
    • 底层红黑树，需要：重载 < 小于号
    • 不需要哈希
  2. std::unordered_map<结构体, T>
    • 底层哈希表，需要：**== + 哈希函数**

四、注意事项

  1. 哈希函数尽量分散，减少哈希冲突；
  2. 作为 key 的结构体成员，不要随意修改（改了哈希值失效，找不到元素）；
  3. C++11 及以上才支持以上写法，竞赛/日常都通用。

一、先搞懂：哈希函数到底是干嘛的？

unordered_map 是哈希表，它要把你的结构体 Node 变成一个数字，才能存进表里。

这个把结构体 → 变成数字的函数，就叫哈希函数。

五、为什么必须写 == ？

因为哈希表会出现冲突：
两个不一样的结构体，可能算出同一个哈希值。

这时系统就用 == 来判断：
到底是不是同一个元素？

所以：

  • 哈希函数 = 定位
  • == = 确认

两个缺一不可！

六、最终总结（你一定能懂）

  1. 哈希函数：把你的结构体变成一个数字。
  2. 系统不会自动变，必须你自己写。
  3. hash<int>()(x) 就是把 x 变成哈希数字。
  4. ^ 或 *31 + 都是为了把多个成员混合成一个数字。
  5. == 用来判断两个 key 是否真的一样。

REALHW133 幻兽防御战

题目链接：REALHW133 幻兽防御战

描述

小红正在守卫一座神秘遗迹，共有 n 只怪兽正向遗迹冲来。
第 i 只怪兽的初始距离为 dist[i]，移动速度为 speed[i]。小红拥有一把每分钟只能发射一次的弩箭，在第 k 分钟开始的瞬间（k=0,1,2,…），小红可以消灭任意一只尚未到达遗迹的怪兽。
对于第 i只怪兽，其到达遗迹的时间为 t[i] =dist[i] /speed[i] 。如果存在某只未被消灭的怪兽满足 t[i] ≦k，则该怪兽会在小红准备好第 k 次射击时或之前抵达并摧毁遗迹，防守立即失败。
请帮小红计算，在遗迹被摧毁前，她最多能消灭多少只怪兽。

输入描述：

输入共三行。
第一行包含一个整数 n（1≦n≦10^5），表示怪兽的数量。
第二行包含 n 个整数 dist[1], dist[2], …, dist[n]（1≦dist[i] ≦10^5），表示每只怪兽的初始距离。
第三行包含 n 个整数 speed[1], speed[2], …, speed[n]（1≦speed[i] ≦20），表示每只怪兽的移动速度。

输出描述：

输出一个整数，表示小红最多能消灭的怪兽数量。

示例1

输入：
3
1 4 4
5 2 3

输出：
2
说明：

样例中三只怪兽的预期到达时间分别为 0.2,2.0,1.33：

- 第 0 分钟：小红准备好第 1 次射击，消灭第 1 只怪兽（到达时间 0.2）。

- 第 1 分钟：小红准备好第 2 次射击，消灭第 3 只怪兽（到达时间 1.33）。

- 第 2 分钟：最后一只怪兽的到达时间为 2.0。此时小红刚准备好第 3 次射击，但怪兽已经同时到达遗迹，防御失败。

因此，小红总共能消灭 2 只怪兽。

REALHW134 遗迹探险家小红

题目链接：REALHW134 遗迹探险家小红

描述

小红正在一座神秘遗迹中收集宝藏。遗迹中共有 n 件宝藏，第 i 件宝藏需要花费 t[i] 分钟来收集，其价值为 p[i] 。
小红的总探险时间不能超过 T 分钟。此外，如果某件宝藏的收集时间 t[i] 严格大于 30 分钟，该宝藏将被视为“重型宝藏”。小红在本次探险中收集的“重型宝藏”总数不得超过 m 个。
每件宝藏最多只能收集一次。请你帮小红计算，在满足时间和重型宝藏数量限制的前提下，她能获得的最大价值总和。

输入描述：

第一行包含三个整数 n,T,m (1≦n≦100,1≦T≦5000,0≦m≦100)，分别表示宝藏总数、最大允许总时间、以及最大允许的重型宝藏数量。
接下来的 n 行，每行包含两个整数 t[i] 和 p[i] (1≦t[i]≦60,1≦p[i]≦1000)，分别表示第 i 件宝藏的收集时间与价值。

输出描述：

输出一个整数，表示小红能获得的最大总价值。

示例1

输入：
4 100 1
20 50
35 60
25 30
40 70

输出：
150

说明：

在样例中，n=4,T=100,m=1。宝藏详情如下：

- 宝藏 1：耗时 20，价值 50（普通）

- 宝藏 2：耗时 35，价值 60（重型，因为 35 > 30）

- 宝藏 3：耗时 25，价值 30（普通）

- 宝藏 4：耗时 40，价值 70（重型，因为 40 > 30）


小红可以选择收集宝藏 1、宝藏 3 和 宝藏 4。

总耗时：20+25+40=85≦100。

重型宝藏数量：仅宝藏 4 一件，数量为 1≦1。

总价值：50+30+70=150。

可以证明这是满足条件的最大价值方案。

ACM模式完整代码

思路及必要说明

动态规划五部曲

1. 确定 dp 数组的下标及含义

dp[j][k] 表示：使用不超过 j 个重型宝藏名额、总时间不超过 k 分钟时，能获得的最大价值。

  • j 的范围：0 到 m（重型宝藏数量限制）
  • k 的范围：0 到 T（总时间限制）
  • 初始值设为 -1 表示该状态不可达

2. 确定递推公式

对于每个宝藏 tr：

  • 如果是重型宝藏（tr.heavy == true）：

    需要消耗1个重型名额，从 dp[j-1][k-tr.time] 转移而来

  • 如果是普通宝藏（tr.heavy == false）：

    不消耗重型名额，从 dp[j][k-tr.time] 转移而来

3. dp 数组的初始化

  • dp[0][0] = 0：不使用任何重型宝藏、不花时间，价值为0（这是唯一的初始可达状态）
  • 其他所有状态初始化为 -1，表示不可达

4. 确定遍历顺序

  • 外层遍历物品：遍历每个宝藏 tr
  • 内层遍历容量：
    • 重型名额 j：从 m 倒序遍历到 0（01背包倒序，避免重复选择）
    • 时间 k：从 T 倒序遍历到 tr.time（01背包倒序）
  • 倒序遍历的原因：这是01背包问题的经典做法，确保每个物品只被选择一次

5. 举例推导 dp 数组

以示例为例：n=4, T=100, m=1

  • 宝藏1：耗时20，价值50（普通）
  • 宝藏2：耗时35，价值60（重型）
  • 宝藏3：耗时25，价值30（普通）
  • 宝藏4：耗时40，价值70（重型）

初始化：dp[0][0]=0，其余为-1

遍历宝藏1（普通，t=20, v=50）后：

  • dp[0][20] = 50

遍历宝藏2（重型，t=35, v=60）后：

  • dp[0][20] = 50（不变）
  • dp[1][35] = 60
  • dp[1][55] = 110（选宝藏1+宝藏2）

遍历宝藏3（普通，t=25, v=30）后：

  • dp[0][20] = 50
  • dp[0][25] = 30
  • dp[0][45] = 80（选宝藏1+宝藏3）
  • dp[1][35] = 60
  • dp[1][55] = 110
  • dp[1][60] = 90（选宝藏2+宝藏3）
  • dp[1][80] = 140（选宝藏1+宝藏2+宝藏3）

遍历宝藏4（重型，t=40, v=70）后：

  • dp[0][45] = 80（宝藏1+宝藏3）
  • dp[1][40] = 70
  • dp[1][60] = 120（宝藏1+宝藏4）
  • dp[1][65] = 100（宝藏3+宝藏4）
  • dp[1][85] = 150（宝藏1+宝藏3+宝藏4）← 最优解
  • dp[1][80] = 140（宝藏1+宝藏2+宝藏3）
  • dp[1][95] = 130（宝藏2+宝藏3+宝藏4）
  • dp[1][100] = 180（宝藏1+宝藏2+宝藏3+宝藏4，但重型=2>m=1，不可行）

最终答案：遍历整个dp数组，最大值为 150（dp[1][85]，使用1个重型名额，耗时85分钟）
